# AdMob 인증 후 광고 게재 확인

## 2026-09-12 확인 상태

- 사용자에게 전달된 AdMob 알림 기준 app-ads.txt 앱 인증 완료.
- 광고 게재 준비 심사는 진행 중. 안내된 예상 기간은 2~3일이며 더 오래 걸릴 수 있음.
- 현재 소스는 개발 모드에서 테스트 광고, 프로덕션에서 실제 광고 단위를 사용함.
- 실제 App Store 배포 바이너리의 광고 설정과 계정 내부 상태는 별도 확인 필요.

## 다음 운영 작업

1. AdMob의 앱 → 모든 앱 보기에서 iOS 앱의 상태가 준비됨으로 바뀌는지 확인한다. 심사 결과 이메일도 확인한다.
2. 계정 알림과 정책 센터에서 별도의 조치 요청이 있으면 처리한다.
3. 준비됨 이후 App Store 앱으로 배너 및 보상형 광고를 확인한다.
4. 계속 미노출이면 해당 iOS 앱/광고 단위의 요청 수, 일치 요청 수, 노출 수를 함께 확인한다. 요청이 없으면 배포 설정·초기화·네트워크를, 요청은 있지만 일치 요청이 없으면 계정 상태·광고 응답 오류를 조사한다. 통계 반영 지연도 고려한다.

## 현재 연령 및 동의 정책

`src/ads/AdMobProvider.tsx`는 모든 요청에 `tagForUnderAgeOfConsent: true` 및 최대 콘텐츠 등급 `PG`를 적용한다. README에 명시된 대로 연령을 구분하지 않으며 UMP 동의 양식을 조회하지 않는다.

Google의 CMP 안내만을 근거로 이 설정을 false로 바꾸거나 모든 사용자에게 성인 동의 양식을 표시하지 않는다. TFUA는 연령 처리 신호이며 일반적인 비개인 맞춤 광고 선택과 동일하지 않다.

성인 대상 개인 맞춤 광고를 도입하려면 먼저 연령 처리 정책을 결정한 다음 다음 작업을 함께 진행한다.

1. AdMob → 개인 정보 보호 및 메시지 → 유럽 규정에서 해당 앱의 메시지, 개인정보처리방침 URL 및 제공 언어를 검토하고 게시한다. 자동 생성 메시지가 있다면 중복 생성 전에 확인한다.
2. UMP에서 앱 시작마다 동의 정보를 갱신하고 필요한 양식을 표시한다. 동의 요청과 광고 요청의 연령 신호를 일치시킨다.
3. `canRequestAds`가 허용할 때 광고를 초기화하고, 필요한 사용자에게 설정 화면의 동의 변경 진입점을 제공한다.
4. 동의 필요/불필요, 거부, 재실행, 네트워크 오류 및 미성년 처리 경로를 테스트한 후 새 앱 버전을 배포한다.

현재 인증 및 심사 대기만을 위해 새 앱 빌드를 배포할 필요는 없다. CMP 코드 변경은 별도의 앱 업데이트가 필요하다.
